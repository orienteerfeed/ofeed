# Anomaly analysis

- Status: implemented
- Issue: https://github.com/orienteerfeed/ofeed/issues/164
- Architecture: follows
  [ADR 0002](../architecture/adr/0002-contracts-and-module-boundaries.md).

## Goal and acceptance criteria

Add an owner/admin-only, read-only insight at
`/events/{eventId}/insights/anomalies` for referee review. Findings are
suspicions, not proof of an early start, and never alter results. Include fast
first splits, off-grid starts and observed start-unit punches. Other issue #164
proposals are outside this version.

First-split analysis uses an imported, unambiguous first ordinary course control
and compares within a class. Skip Score-O, unordered results, missing courses,
ambiguous repeated first controls and invalid or repeated matching splits. Use
positive OK/Finished splits as references. Evaluate any competitor with a usable
split against at least eight other references. Flag only a split below half
their median, at least 30 seconds faster than that median, and below median
minus three MAD (median absolute deviation). No fallback to first stored split.
All start modes can participate.

Start checks use the effective class/event start mode and run only for StartList
and WaveStart. Infer the grid from at least five distinct timestamps. The unique
modal adjacent gap must be at least 10 seconds and occur at least three times.
Use the unique most frequent phase and require at least 80% support within one
second; flag starts more than one second from its nearest grid point. Collapse
identical wave timestamps. Ambiguous or unsupported grids are skipped, not
declared clean.

Assigned, non-superseded Punch records with controlCode 0 provide start-unit
warnings for StartList/WaveStart. Retain all observed times under one
competitor. Missing observations do not establish absence of start punching.
Current startTime may have replaced the original scheduled start, which is not
separately stored; no exact scheduled/actual comparison or SIAC station
identification is claimed.

## API and UI

Add JWT owner/admin GraphQL `eventAnomalyInsight(eventId: String!)` with shared
Zod contracts. Authorize before event-scoped batched reads; keep calculations in
the competitor service. No persistence, migrations, subscriptions or ingestion
changes. Return competitors with structured findings and per-class/per-rule
coverage, including evaluated and total counts and skip reasons.

Add a catalog card, route, explanatory text, rule/affected-competitor summaries,
class/type/search filters, stable class/name/ID ordering, pagination of 25 and
explicit refresh. Filters never change statistical references. One row per
competitor retains every finding. Show evidence in expandable details. Display
event-timezone dates. CSV/print cover all filtered rows, evidence, coverage,
summaries, event, filters and generation time; escape HTML and CSV and
neutralize spreadsheet formulas using existing insight helpers.

Distinguish loading, error/retry, no findings, no matching filters and skipped
checks. Retained data after refresh failure is stale; exports remain disabled
until recovery. Support accessible responsive tables and cs/en/de/es/sv/fr.

## Test plan

Test statistical boundaries, zero MAD, insufficient peers, class isolation,
missing/ambiguous controls and splits, unsupported modes and ordered courses.
Test minute/half-minute/offset/wave grids, gaps, outliers, ties, tolerance and
inherited start modes. Test assigned versus superseded/unmatched punches. Verify
JWT/owner/admin access before reads, event isolation, real GraphQL shape, filter
combinations, multi-reason rows, pagination-independent exports, escaping, stale
data and recovery. Run shared build/types, affected client/server tests,
client/server/GraphQL types, lint and formatting. Verify browser navigation,
mobile, CSV and print where available; record unavailable checks explicitly.

- New browser test files pass client types, focused lint and formatting checks.
  No database migration or deployment was needed or performed.

## Reproducing the browser checks

From the repository root, with the documented Node/pnpm versions and installed
Playwright browsers:

```bash
pnpm --filter ./apps/client exec playwright test e2e/anomaly-insight.spec.ts --workers=2 --reporter=line
```

The existing Playwright configuration starts or reuses Vite on port 3000. The
fixture needs no database, account, production credentials or external service.
Screenshots are stored in the ignored `apps/client/test-results/` directory.
